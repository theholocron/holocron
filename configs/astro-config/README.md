# Astro Config

An [Astro configuration](https://docs.astro.build/en/reference/configuration-reference/) factory for theholocron docs sites.

## Installation

```bash
pnpm add -D @theholocron/astro-config
```

`defineConfig()` always wires in the `@astrojs/react` integration (needed by
`@theholocron/docs-theme` consumers that render React components in their
docs), so `@astrojs/react`, `react`, and `react-dom` are declared as
`peerDependencies` — install them alongside this package:

```bash
pnpm add -D @astrojs/react react react-dom
```

Without them, `pnpm install` still succeeds (with an unmet-peer warning), but
`astro build`/`astro dev` fails at build time trying to resolve
`@astrojs/react/server.js` — Vite resolves that import from the consuming
project's own `node_modules`, not from this package's, so the peer can't be
satisfied transitively.

## Usage

Pass `starlight` and `docsTheme` from your own imports alongside the docs config. This keeps Astro's module loader in control of those framework imports:

```ts
// astro.config.ts
import starlight from "@astrojs/starlight";
import { docsTheme } from "@theholocron/docs-theme";
import { defineConfig } from "@theholocron/astro-config";
import clientsConfig from "@theholocron/clients-docs";

export default defineConfig({
  docs: clientsConfig,
  importMetaUrl: import.meta.url,
  starlight,
  docsTheme,
});
```

### Custom sidebar label

By default the sidebar group label is derived from `docs.sidebar[1].label`. Override it when the label differs:

```ts
import starlight from "@astrojs/starlight";
import { docsTheme } from "@theholocron/docs-theme";
import { defineConfig } from "@theholocron/astro-config";
import holocronConfig from "@theholocron/holocron-docs";

export default defineConfig({
  docs: holocronConfig,
  importMetaUrl: import.meta.url,
  starlight,
  docsTheme,
  sidebarLabel: "Reference",
});
```

### API reference from TSDoc

`apiReference()` generates a package's API reference from its TSDoc comments each time the docs are built or served (nothing generated is committed). It returns a Starlight plugin and a sidebar group:

```ts
import { apiReference, defineConfig } from "@theholocron/astro-config";
import { createStarlightTypeDocPlugin } from "starlight-typedoc";

const arrayUtils = apiReference({
  createPlugin: createStarlightTypeDocPlugin,
  root: new URL("./", import.meta.url),
  package: "utils/array-utils",
});

export default defineConfig({
  docs: {
    name: "Utils",
    github: "utils",
    sidebar: [{ label: "array-utils", items: [{ label: "Overview", slug: "array-utils" }, arrayUtils.group] }],
  },
  plugins: [arrayUtils.plugin],
  starlight,
  docsTheme,
});
```

`entryPoints` (default `["src/index.ts"]`, relative to the package) and `label` (default "API reference") are optional. `starlight-typedoc` ships TypeScript source, so, like `starlight` and `docsTheme`, you import it in your own config and pass it in; install `starlight-typedoc`, `typedoc` and `typedoc-plugin-markdown` in the site.

## What it generates

- `site` — only when you pass it (for example `https://docs.theholocron.dev`); without it Starlight cannot generate a sitemap
- `base` — `/${docs.slug}`
- Starlight integration with the `@theholocron/docs-theme` plugin
- GitHub social link to `https://github.com/theholocron/${docs.slug}`
- Sidebar with an Overview link and an autogenerated sub-pages group
