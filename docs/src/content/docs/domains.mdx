DNS for `theholocron.dev` lives in one place: Cloudflare (the zone's nameservers are `rosalyn.ns.cloudflare.com` and `dan.ns.cloudflare.com`). Other providers serve traffic, but none of them holds a DNS zone for the domain. Sentinel's compute is on Vercel; its record is still a Cloudflare record.

This page is the inventory. It was written from `dig` and `curl` on 2026-11-02; the full Cloudflare record list was not read. The last column says which names [`holocron doctor dns`](/holocron/commands/doctor-dns/) checks, so a drift in those is caught rather than found by a visitor.

A proxied record hides the target behind Cloudflare, so `dig` shows Cloudflare addresses for `wiki` and `comlink`; that is how the proxy flag was read for those two. The Sentinel record has to stay DNS-only: a proxied record breaks the certificate Vercel issues for it. `doctor dns` reads the expected target from Vercel (read-only) and fails the row when the record is gone, points elsewhere or is proxied.

The apex also carries a verification `TXT` record for Apple. Any change to the apex must keep it and the mail records above.
