The `op` CLI must be installed separately. Install it from [1password.com/downloads/command-line](https://1password.com/downloads/command-line/) or via Homebrew:

```bash
brew install --cask 1password/tap/1password-cli
```

## Config

```ts
providers: {
  vault: ["1password", {
    // Optional: 1Password vault name where items live. Only `list()` needs it.
    vault: "acme-app",
    // Optional: 1P account UUID (--account flag on every op call)
    account: "ABCDEFGHIJKLMNOPQRSTUVWXYZ",
  }],
}
```

## Authentication

**On laptop:** Sign in via the 1Password desktop app or `op signin`. The plugin uses the active session automatically.

**In CI:** Create a service account token and set it in your workflow:

1. Go to [my.1password.com/developer-tools/service-accounts](https://my.1password.com/developer-tools/service-accounts)
2. Click **New Service Account**, name it (e.g. "CI"), and grant access to the vaults the plugin needs
3. Copy the token (shown once) and store it as a repository secret named `OP_SERVICE_ACCOUNT_TOKEN`

```yaml
env:
  OP_SERVICE_ACCOUNT_TOKEN: ${{ secrets.OP_SERVICE_ACCOUNT_TOKEN }}
```

`holocron auth set 1password` does not store a token — it prints the `AUTH_HINT` instead.

## Secret reference format

1Password item references follow the format `op://Vault/Item/field`:

```bash
# Read a secret
op://acme-app/database/password
```

In the `vault` capability this format is used with `vault.read(reference)`.

## Using it for your tokens (`credentials`)

The plugin can also be where the CLI finds its own tokens, ahead of the keyring: one 1Password Environment holds them all and Touch ID asks once per command. The Environment is named in `holocron.config.ts` (`credentials.environment`), not in the plugin options. Creating it is a one-time step by hand; see [Credentials providers](/holocron/tokens/#credentials-providers).

```ts
providers: { credentials: ["1password"] },
credentials: { environment: "Holocron" },
```

`holocron doctor credentials` checks the Environment: it exists, holds every variable the configured plugins take, and which spelling of its name matched. It asks `op environment secret list` without `--reveal`, so no value is read.

## What `vault` provides

- `read(reference)` — reads a secret by `op://Vault/Item/field` reference
- `write(reference, value)` — writes a secret value
- `list()` — lists the item titles in the configured vault (needs `vault`)
- `readEnvironment?(name or id)` — reads every variable of a 1Password Environment, by name or id (supports `holocron secrets sync`). `op environment read` takes only an id, so this goes through `op environment secret list`

There is no `ensureProject` or `ensureEnvironment`: the vault and an Environment are created in the 1Password app, once. There is no `environments()` either, because no `op` command lists Environments.
