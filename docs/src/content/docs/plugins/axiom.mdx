## Self-contained activation

Structured log output to Axiom is handled by
[`@theholocron/logger`](/holocron/logging/) — its Axiom transport reads
`HOLOCRON_AXIOM_TOKEN` + `HOLOCRON_AXIOM_DATASET` (fallbacks: `AXIOM_TOKEN` +
`AXIOM_DATASET`) directly at startup. **This plugin does not ship log lines.**

The `logs` provider entry is used only by `holocron setup` (to provision the
CLI's dataset) and `holocron doctor` (to verify the configured dataset is
reachable). Each service has its own dataset (the CLI `holocron`); its environments share it and are told apart by the
`env` field on each line.

```bash
# The org variable HOLOCRON_AXIOM_DATASET, synced from 1Password and passed to the CLI by the sync workflows
export HOLOCRON_AXIOM_DATASET=holocron
```

Locally, Axiom is opt-in: with no token or no dataset, nothing ships.
`HOLOCRON_AXIOM_DATASET` is **not a secret**.

## Config

```ts
providers: {
  logs: "axiom",
}
```

No options are required. To pin the dataset that `holocron doctor` checks
independent of the env var:

```ts
providers: {
  logs: ["axiom", { dataset: "holocron" }],
}
```

## Authentication

1. Go to [app.axiom.co/settings/api-tokens](https://app.axiom.co/settings/api-tokens)
2. Create an API token with permission to **read** and **create** datasets
3. Store it:

```bash
holocron new token axiom <TOKEN>
```

Or via env var:

```bash
export HOLOCRON_AXIOM_TOKEN=<TOKEN>
# Also recognized:
export AXIOM_TOKEN=<TOKEN>
```

## What `logs` provides

- `describe()` — returns the provider name and required env var keys (`HOLOCRON_AXIOM_TOKEN`, `HOLOCRON_AXIOM_DATASET`)
- `verifyToken()` (`check token`, `doctor tokens`) — reads the token's user; an API token may not (403), so it then asks for a dataset that does not exist and accepts a 404 as proof the token is valid and may read datasets
- `whoami()` — fetches the configured dataset to verify the token and its reachability
- `readDataset(name)` — reads a dataset without changing it: whether it exists (a 404 is `exists: false`, never created) and its `retentionDays` when Axiom returns one. Used by [`holocron doctor logs`](/holocron/commands/doctor-logs/)
- `checkToken()` — asks for a dataset that cannot exist: a 404 means Axiom accepts the token, a 401 means it refused it; anything else throws, so it says nothing about the token
- `ensureDataset(name)` — create the dataset if it does not exist; returns whether it already existed. Idempotent.

## Example

```ts
import { createPlugin } from "@theholocron/holocron-plugin-axiom";

const plugin = createPlugin({ token: process.env.HOLOCRON_AXIOM_TOKEN });
const logs = plugin.capabilities.logs();

const { alreadyExists } = await logs.ensureDataset("holocron");
console.log(alreadyExists ? "dataset exists" : "dataset created");
```
