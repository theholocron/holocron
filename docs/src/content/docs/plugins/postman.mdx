## Config

```ts
providers: {
  // Single Postman sync
  tooling: ["postman", {
    workspace: "Holocron",
    collectionFiles: ["postman/app.postman_collection.json"],
    envFiles: ["postman/app.postman_environment.json"],
  }],

  // Or alongside other tooling providers (multi)
  tooling: [
    ["postman", { workspaceId: "abc123-..." }],
  ],
}
```

### Options

| Option            | Required | Description                                                                                                                |
| ----------------- | -------- | -------------------------------------------------------------------------------------------------------------------------- |
| `workspace`       | One of   | Workspace name. `sync` finds the workspace with this name, and makes it when there is none                                 |
| `workspaceId`     | One of   | Postman workspace id. Wins over `workspace`, so a workspace that already exists under another name can be named explicitly |
| `workspaceType`   | No       | `personal` (default) or `team`: the type of a workspace `sync` makes                                                       |
| `specFile`        | No       | Path to an OpenAPI JSON file, uploaded to Spec Hub and imported as a collection                                            |
| `specName`        | No       | Spec Hub name; defaults to the spec's `info.title`                                                                         |
| `collectionName`  | No       | Name of the collection imported from `specFile`; defaults to `specName`                                                    |
| `collectionFiles` | No       | Paths to hand-written Postman collection JSON files; each is matched to a collection of the workspace by its `info.name`   |
| `envFiles`        | No       | Paths to Postman environment JSON files, matched to environments of the workspace by `name`                                |

`sync` needs at least one of `specFile`, `collectionFiles` and `envFiles`. Paths are relative to the repository root.

One workspace holds every app of the organization: each app is a collection in it (with its own environment), and the folders inside a collection group that app's requests. Give each app's `holocron.config.ts` the same `workspace` name and its own `collectionFiles` and `envFiles`.

## Authentication

1. Sign in to [web.postman.co](https://web.postman.co)
2. Click your avatar (top-right) → **Settings** → **API Keys**
3. Click **Generate API Key**, give it a name, and copy the key — it starts with `PMAK-`

```bash
holocron new token postman PMAK-xxx
```

Or via env var:

```bash
export HOLOCRON_POSTMAN_TOKEN=PMAK-xxx
```

## What `tooling` provides

- `sync()` — reconciles the workspace with the repo's API definitions: finds or makes the workspace, upserts the Spec Hub spec and replaces its imported collection (`specFile`), replaces or creates each hand-written collection in place (`collectionFiles`, so its uid and links stay), and finds or creates each environment (`envFiles`). A secret an environment file leaves empty keeps the value the environment already holds, so a sync never blanks a secret set in Postman. That read-back is not yet confirmed against the live API: Postman may mask a secret in its response.
- `export()` — writes each collection file in Postman's collection schema 3.0 YAML layout, one folder per collection, by running `postman collection migrate <file> --output <dir>` with the Postman CLI. It is used by [`holocron export requests`](/holocron/commands/export-requests/) and needs no API key and no workspace. An environment file is reported as not exported, because the command converts collections only. A dry run migrates into a temporary folder, lists the files and removes it. The CLI is a Homebrew cask (`brew install --cask postman-cli`); in this repo `./.humans/setup.sh` installs it, and `./.humans/setup.sh doctor` reports when it is missing. Not yet verified against the real CLI.
- `doctor()` — returns `{ ok, message }` indicating whether the key is valid and the workspace is reachable; a `workspace` name that does not exist yet is reported as one `sync` will make, never made by `doctor`

The full [API reference](/holocron/plugins/holocron-plugin-postman/api/readme/) is generated from the package's TSDoc comments.
