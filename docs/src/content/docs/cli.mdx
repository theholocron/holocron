`@theholocron/cli` is the `holocron` command. It reads one `holocron.config.ts`, maps each **capability** (source, vault, deployment, monitoring, notifications and so on) to a **provider** plugin, and runs the commands that set up and operate a repository against those providers. The CLI never talks to a vendor directly: the `@theholocron/holocron-plugin-*` packages do (see the [plugin overview](/holocron/plugins/overview/)).

## Install

```bash
pnpm add -g @theholocron/cli@alpha
holocron --help
```

Or per project, so the plugin packages resolve next to it:

```bash
pnpm add -D @theholocron/cli@alpha
```

The package is published on npm under the `alpha` dist-tag, and its API may still shift before a stable v2.

## How it fits

| Package                                          | Role                                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `@theholocron/cli`                               | The command tree, the config schema and the plugin loader                            |
| [`@theholocron/datapad`](/holocron/datapad/)     | Finds and loads `holocron.config.*` and `astromech.config.*`                         |
| [`@theholocron/astromech`](/holocron/astromech/) | The task runner behind `holocron run`, `holocron run ci` and the generated workflows |
| [Plugins](/holocron/plugins/overview/)           | One provider per capability, loaded on demand                                        |
| [`@theholocron/sentinel`](/holocron/sentinel/)   | The GitHub App that validates the same config on every repo                          |

## Key points

- **Interactive mode.** Run `holocron` with no command, a parent command with no subcommand, or a command missing a required argument, and you get a prompt in place of a `--help` dead end. The menu mirrors the command tree, and typing searches it.
- **Execution contexts.** Each command is tagged `global`, `repo-aware` or `workspace` by how much of a repo it needs. A bare global install can run the first kind only. See [Execution Contexts](/holocron/execution-contexts/).
- **One config file.** Providers, repo settings, the task manifest and the notifications layout all live in `holocron.config.ts`, optionally with the task manifest split into `astromech.config.ts`. See [Configuration](/holocron/config/) and `holocron config show`.
- **Capabilities.** The interfaces providers implement are listed on [Capabilities](/holocron/capabilities/).
- **Auth.** Tokens are stored in the OS keyring with `holocron auth set`, or read from environment variables. The [Token Reference](/holocron/tokens/) lists every token and its scopes.
- **Server as code.** A notifications provider can declare a whole chat server in the config, and the CLI applies and checks it. See [Server as Code](/holocron/server-as-code/).
- **Logging and telemetry.** See [Logging](/holocron/logging/) and [Telemetry](/holocron/telemetry/) (`HOLOCRON_TELEMETRY=false` turns the latter off).
