---
title: "notifications create-server"
description: Create the server a layout describes, apply it, invite its owner and hand it over.
---

```bash
holocron notifications create-server --name <name> --owner <member id> [--provider <name>] [--force] [--resume] [--dry-run]
```

Builds the server from nothing. A bot can create a server (Discord allows it while the bot is in fewer than ten), and a server it creates already has the bot in it, so there is no invite step for the bot. The command then:

1. **creates** the server, owned by the bot at first;
2. **writes the new server id** into your `holocron.config.ts` (`guildId`), so every other command finds it. If the file has no single `guildId: "…"` to replace it leaves the file alone and tells you what to set;
3. **applies the whole layout**, exactly as [`notifications setup`](/holocron/commands/notifications-setup/) does (the bot owns the server, so it may do everything, including turning community features on, with no elevation step);
4. **invites the owner**: a single-use link into the system channel (else the rules channel, else the first channel), valid for a day;
5. **waits for the owner to join** (up to 15 minutes, looking every few seconds), then **hands the server over** to them.

Ownership can only go to someone who is already in the server, which is why the owner joins first. Until then the bot owns it and [`doctor notifications`](/holocron/commands/doctor-notifications/) says so (step 16).

## Options

| Option              | Default | Description                                                                                                                                                                                            |
| ------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--name <name>`     | —       | What the new server is called (not needed with `--resume`)                                                                                                                                             |
| `--owner <id>`      | —       | The member id, on the provider, of the person who will own it. For Discord, the user id: Developer Mode → right-click yourself → Copy User ID. After `notifications link` it is also in the links file |
| `--provider <name>` | —       | Which `notifications` provider, when more than one can create a server                                                                                                                                 |
| `--force`           | `false` | The config already names a server (`guildId`): create another anyway and replace the id. Without it the command refuses, so it can never make a second server by accident                              |
| `--resume`          | `false` | The server exists and is set up (an earlier run stopped at the invite): skip creating and applying, make a fresh invite and finish the hand-over                                                       |
| `--dry-run`         | `false` | Say what would happen without calling the provider                                                                                                                                                     |

## When something stops halfway

- **The layout fails to apply.** The server exists and the bot owns it. Nothing is handed over. Fix what failed and run `notifications setup`, then `create-server --resume --owner <id>`.
- **The owner does not join in time.** Same state. Open the invite (or run `--resume` for a new one) and run `create-server --resume --owner <id>`.
- **The config file could not be edited.** The command carries on and prints the id to set by hand.

## Limits

- Discord lets a bot create a server only while it is in fewer than ten. Past that, `POST /guilds` is refused and the command says so.
- A new server starts with Discord's own default channels (such as `general`). The layout is added to them; nothing is deleted.
- Anything the API cannot do stays manual, as for [`setup`](/holocron/commands/notifications-setup/): the developer-portal settings of the bot itself belong to the application, not to a server, so they carry over.
