---
title: "publish"
description: Publish @theholocron/* packages to npm — steady-state (CI/OIDC) or the one-shot Trusted Publishing bootstrap.
---

```bash
holocron publish [--tag <tag>] [--otp <code>] [--provenance] [--skip-already-published] [--dry-run]
holocron publish --initial [--tag <tag>] [--otp <code>] [--dry-run]
holocron publish --sync-trust <old-file> <new-file> [--repo <owner/repo>] [--dry-run]
```

Three modes:

- **Steady-state** (no flags, or `--provenance`/`--skip-already-published`) — the `exec.publishCmd` a `release.config.ts` should call. Runs under CI, authenticated via OIDC automatically — no interactive step. Replaces each repo's hand-typed `pnpm -r --filter=./packages/* publish ...` shell with one uniform invocation (config-resolution workstream, [#676](https://github.com/theholocron/holocron/issues/676)).
- **`--initial`** — one-shot bootstrap publish for packages that haven't been registered on npm yet. Solves the chicken-and-egg problem: npm Trusted Publishing (OIDC) requires the package to exist before you can configure it, so the first publish must happen with browser auth.
- **`--sync-trust`** — bulk-migrate npm Trusted Publisher config to a new workflow filename.

## Migrating Trusted Publisher config (`--sync-trust`)

npm's Trusted Publisher config is tied to a specific workflow **filename** per package. Renaming the release workflow (e.g. `release.yml` → `delivery.publish.yml`) breaks OIDC publish (`ENEEDAUTH`) for every package still registered under the old filename until each one is updated to match.

```bash
holocron publish --sync-trust release.yml delivery.publish.yml
```

For every public package (auto-discovered the same way as `--initial`): revokes the existing trust config if its `file` doesn't already match, then creates a new one pointing at the new filename. Already-migrated packages are skipped, so it's safe to re-run.

**This can't run unattended.** npm's `trust` mutations — and reads, once a short-lived OTP grant lapses — require a fresh interactive browser 2FA approval. There's no token that bypasses this (npm's own docs: Granular Access Tokens with the bypass-2FA option are explicitly unsupported for trust endpoints). When the command hits this, it stops immediately, prints the `authUrl` to open and approve, and returns a `needs-auth` result for that package — open the link, approve it, and re-run.

See [issue #689](https://github.com/theholocron/holocron/issues/689) for the full background.

## Workflow

```bash
# Steady-state — the exec.publishCmd release.config.ts calls in CI.
pnpm exec holocron publish

# Skip packages whose exact version already exists on npm — for repos
# with many independently-versioned packages where a release doesn't
# bump every one (configs' own case).
pnpm exec holocron publish --skip-already-published
```

```bash
# 1. Build everything
pnpm install --frozen-lockfile && pnpm build

# 2. Bootstrap publish — logs in via `npm login --auth-type=web` automatically
#    if `npm whoami` shows no session, then publishes and prints Trusted
#    Publisher config links.
holocron publish --initial --otp 123456
```

After `--initial` runs, visit each package's npm page → Settings → Trusted Publishers to complete the setup (see [Self-hosting](../self-hosting)).

## Repo layouts

- **Monorepo** (a `packages/` directory exists): publishes every public `packages/*` workspace via `pnpm -r --filter=./packages/*` (or, with `--skip-already-published`, one workspace at a time via `pnpm --filter <dir> publish`).
- **Single package** (no `packages/` — most `node-template` scaffolds): publishes the root package directly via a plain `pnpm publish`.

The command fails loudly — `nothing to publish` — rather than silently no-op'ing when it finds no publishable package in either layout.

## Options

| Option                     | Default                                         | Description                                                                                          |
| -------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `--initial`                | `false`                                         | Runs the one-shot bootstrap publish instead of the steady-state path                                 |
| `--tag`                    | `alpha` (`--initial`) / `latest` (steady-state) | npm distribution tag                                                                                 |
| `--otp`                    | —                                               | TOTP code from your authenticator (if 2FA is required for writes)                                    |
| `--provenance`             | `true`                                          | Steady-state only: publish with `--provenance`                                                       |
| `--skip-already-published` | `false`                                         | Steady-state only: check `npm view <pkg>@<version>` first, skip a package whose exact version exists |
| `--sync-trust`             | —                                               | `<old-file> <new-file>` — migrate every package's Trusted Publisher config                           |
| `--repo`                   | `theholocron/holocron`                          | `owner/repo` for the Trusted Publisher config (`--sync-trust` only)                                  |
| `--dry-run`                | `false`                                         | Print what would happen without making any npm calls                                                 |

## Notes

- Packages marked `"private": true` in their `package.json` are skipped automatically.
- Steady-state authenticates via CI's OIDC token exchange — no `npm whoami`/login step, no Trusted Publisher next-steps printout (both `--initial`-only).
- `--initial`: if `npm whoami` shows no authenticated session, the command runs `npm login --auth-type=web` itself (interactive, browser-based) before continuing. If the command detects `NPM_TOKEN` in env, it prints a reminder to revoke the token afterward.
- If the (bulk, non-`--skip-already-published`) publish fails with `EOTP`, the corrected command with `--otp` is printed.
