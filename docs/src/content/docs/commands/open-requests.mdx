---
title: "open requests"
description: Open the request tool's workspace with its secrets filled in from the layers' vault Environments.
---

```bash
holocron open requests [--environment <layer>...] [--to <provider>] [--dry-run] [--yes]
```

A signed request needs a secret: Sentinel's `webhookSecret`, Comlink's `sentrySecret`. The request files leave it blank on purpose (they are shared with other tools and committed), so each person used to paste it into Bruno by hand, once per environment, on every machine. `open requests` fills it from the layer's 1Password Environment (`<org/repo> - <layer>`) instead, and starts Bruno with it.

## Layers

Each Bruno environment is wired to a layer, and each layer's secret has its own name in the private file: the layer word in capitals, then the entry (`DEV_SENTINEL_WEBHOOK_SECRET`, `PROD_SENTINEL_WEBHOOK_SECRET`). So Bruno's environment switcher picks the secret together with the environment: choosing `Sentinel (prod)` signs with the prod secret, never the dev one.

- `--environment` names the layers to load: `local`, `dev` or `prod`, repeated or comma-separated (`--environment dev --environment local`, `--environment dev,local`). `ci`, `test` and anything else is refused with the allowed words.
- **The default is `dev` alone. `prod` is never loaded unless you name it** (`--environment prod`). Only the named layers are read from 1Password.
- Sentinel has `Sentinel (local)`, `Sentinel (dev)` and `Sentinel (prod)`, wired to the layers of the same name. **Comlink has one environment and is prod only for now**, so its secret loads only with `--environment prod`.
- A layer you did not load has no value. Picking its environment in Bruno and sending a request fails with "variables that could not be resolved", naming the variable, for example `process.env.PROD_SENTINEL_WEBHOOK_SECRET`: that layer was not loaded; quit Bruno and start it again with `--environment prod`. Nothing is written in its place, because a placeholder secret would sign a request with a bogus value. The command also prints a `layers` row, `loaded: dev; not loaded: local, prod`, with the variables behind each layer that was left out.
- It fails closed: if any layer you named cannot give a declared entry (missing, blank, or its Environment cannot be read), the run stops with a failing row that names the layer and the entry, and nothing starts. A half-loaded set would sign with nothing.

## What it does

1. Asks the `tooling` provider that can open its workspace (`Tooling.open`; Bruno's) which values the workspace reads. Each secret is a reference, `{{process.env.DEV_SENTINEL_WEBHOOK_SECRET}}`, that [`sync requests`](/holocron/commands/sync-requests/) writes into `.bruno/` from the provider's `secretRefs` and `environmentLayers` options. A secret with no reference is listed by name and filled by nobody.
2. Reads each named layer's Environment in memory and takes **only** the entries the references name for that layer. An entry that layer lacks, or holds blank, is a failing row that names it, and nothing starts.
3. Refuses when Bruno is already running. A second instance would not see the values (or would see another set), so the command asks you to quit it and never kills it. A lock file in `.holocron/.private/` covers two launches at the same moment.
4. Writes the values to `.holocron/.private/requests.env` (mode 0600, only when git says the path is ignored, never over an existing file), links `<collection>/.env` to it, and starts Bruno **in the foreground** with the workspace folder. Bruno reads `{{process.env.NAME}}` from that `.env`, and a script that reads `bru.getEnvVar("webhookSecret")` gets the resolved value, so the signing scripts need no change.
5. When Bruno quits (or on Ctrl-C), removes the file, the links and the lock. The same happens on an error and on `SIGINT`, `SIGTERM`, `SIGHUP` and exit.

```ts
providers: {
	tooling: [
		[
			"bruno",
			{
				collectionFiles: ["apps/sentinel/api/webhook.collection.json"],
				envFiles: ["apps/sentinel/api/webhook.environment.json"],
				// The secret variable, and the 1Password entry that holds its value in each layer.
				secretRefs: { webhookSecret: "SENTINEL_WEBHOOK_SECRET" },
				// The layer each Bruno environment's secrets come from.
				environmentLayers: { "Sentinel (local)": "local" },
			},
		],
	],
},
```

Run `holocron sync requests` after changing either option, and commit `.bruno/`. The request files keep a blank secret, so Postman is unaffected.

## How long the values live

The values are in plaintext in `.holocron/.private/requests.env` for as long as Bruno runs, which is the length of the session: the command stays in the terminal until you quit Bruno. Nothing can run on `SIGKILL` or a crash, so the file starts with a marker line, and the next run removes a leftover that has it and refuses a `.env` or values file without it.

## Rules

- **A value is never printed.** Rows name entries, layers and paths only. `--dry-run` lists, for each loaded layer, the names it would fill and the route, and reads, writes and starts nothing.
- **It asks first.** Without `--yes` it asks before it reads and writes; without a terminal and without `--yes` or `--dry-run` it refuses.
- **It never overwrites.** A `.env` in a collection folder that is not a link to the values file and has no marker line is somebody else's and is refused.
- **Concealed values are read on purpose.** The secrets are concealed entries. This command is the one exception to "a concealed value is never handed over": it reads only the layers you name, only the names the workspace's references list, only for a process you start on your own machine, and never gives one to a plugin or a log.
- **It needs the plugins and a vault.** It is a `workspace` command, and the `vault` provider must be able to read an Environment's entries (1Password).
- **macOS by default.** The program is `/Applications/Bruno.app/Contents/MacOS/Bruno`; the `bruno` provider's `app` option sets another. Windows is refused (no enforced file modes).
