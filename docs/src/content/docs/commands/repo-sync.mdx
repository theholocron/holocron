---
title: "repo sync"
description: Sync repository metadata from holocron.config.ts to GitHub and local files.
---

```bash
holocron repo sync [steps..] [--repo owner/name] [--dry-run]
```

`sync` pushes metadata defined in `holocron.config.ts` to the configured `source` provider (GitHub) and to local files. Run it after updating any of the synced fields in config.

## Steps

Pass specific step names to run only those steps. Omit to run all.

```bash
holocron repo sync                               # run all steps
holocron repo sync labels properties             # run only labels and properties
```

| Step          | What it syncs                                                                                                                                                                            | Requires provider token      |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `labels`      | GitHub labels — upserts canonical set, deletes stale ones                                                                                                                                | Yes (`HOLOCRON_ADMIN_TOKEN`) |
| `properties`  | Org-level custom properties (`repo.properties`)                                                                                                                                          | Yes                          |
| `teams`       | Team repository access (`repo.teams`)                                                                                                                                                    | Yes                          |
| `topics`      | GitHub topics (`repo.topics`)                                                                                                                                                            | Yes                          |
| `keywords`    | `package.json#keywords` — set from `repo.topics`                                                                                                                                         | No                           |
| `description` | `package.json#description` and GitHub repo description                                                                                                                                   | No (local) / Yes (GitHub)    |
| `homepage`    | `package.json#homepage` and GitHub repo website field                                                                                                                                    | No (local) / Yes (GitHub)    |
| `readme`      | Regenerates the README Installation/Usage block and the scripts table; fails when the README tells the reader to run a task script the package lacks (`pnpm test` with no `test` script) | No                           |
| `workflows`   | `.github/workflows/*.yml` thin callers from `tasks`                                                                                                                                      | No                           |
| `private`     | `.holocron/.private/.gitkeep` and the `.gitignore` block that ignores everything else in that directory                                                                                  | No                           |
| `scripts`     | `package.json#scripts` — the `holocron` entry + one script per runnable task in `tasks`                                                                                                  | No                           |
| `turbo`       | `turbo.json` — generated from the fan-out-eligible tasks in `tasks`                                                                                                                      | No                           |
| `wiki`        | Publishes engineering docs to the wiki                                                                                                                                                   | No                           |

Local steps (everything except `labels`, `properties`, `teams`, `topics`) write to the local filesystem. `description` and `homepage` also push to GitHub when a `source` plugin is configured; running without a token skips the GitHub push but still updates local files.

### `private`

`.holocron/.private/` is the one place for files that hold secrets, such as the `.credentials` file [`auth export`](/holocron/commands/auth-export/) and [`github-app create`](/holocron/commands/github-app-create/) write. The step writes an empty, tracked `.gitkeep` there and a managed block in `.gitignore`:

```text
# managed by holocron setup — private directory
.holocron/.private/*
!.holocron/.private/.gitkeep
# end managed by holocron setup — private directory
```

The block is merged into the `.gitignore` already there; the rest of the file is kept. `repo setup` writes the same bytes, and `holocron probe generated check` fails when either differs. A command that writes to the directory refuses when git does not ignore the path and tells you to run `holocron repo sync`.

### `scripts`

Merges into `package.json#scripts` — only the managed keys are touched, every other script is left alone:

- `holocron` → the value of `holocronScript` (default `"holocron"`, the installed bin)
- one script per runnable task in `tasks`, named by the task id in its script spelling (`test:unit`, `deploy:preview`) and one per suite (`test`, `lint`, `scan`):
  - in a pnpm workspace with a `turbo.json`, `turbo run <task>` for a task that runs in each package and for each suite, and the tool's own command (`prettier --write .`, `knip`) for a task that runs once at the root. The `holocron` bin is built from this repo, so on a fresh clone it does not exist yet while turbo does;
  - in a single package, `holocron run <task> --` (`holocron run test unit --` for a suite member). The trailing `--` is there because pnpm appends arguments as typed.
- a task with no local command (`scan:code`, `release`) has no script in a workspace.

A root script that already holds a real command for a task turbo runs in each package (a root that is itself a package) is left alone, because turbo would call the root script, which would call turbo again. Any other hand edit of a script this step owns is overwritten, and `holocron probe generated check` fails until it is. That check also fails a package script named like an npm lifecycle word (`publish`, `install`) or a suite (`test`, `lint`), and a leaf script in a package that calls `turbo run` or `holocron run`.

Set `syncScripts: false` in `holocron.config.ts` to disable the step entirely.

### `turbo`

Generates `turbo.json` — full ownership, never hand-edited. In a pnpm workspace it also writes each suite (`test`, `lint`, `scan`) as a task with no script that depends on its leaves, and a `//#<task>` root task (uncached) for each task of a suite that runs once at the root, such as `lint:markdown`. Only tasks with real per-workspace fan-out (a build/compile/test step — `build`, `typecheck`, `test:unit`, `lint:code` today) get an entry; whole-repo, single-run tools (prettier, gitleaks, commitlint, yamllint, …) stay off the file and run once, un-fanned-out, the same way they already do. Skipped with no write when nothing in `tasks` is fan-out-eligible.

A task entry's `turbo.passThroughEnv` appends extra env vars to that task's cache-key hashing, on top of the registry default (a no-op on a task with no fan-out config to add onto):

```typescript
tasks: [{ name: "build", turbo: { passThroughEnv: ["SENTRY_AUTH_TOKEN"] } }];
```

`turbo.inputs` appends input globs the same way. `turbo.dependsOn` appends tasks the task waits for, for a build it loads without listing the package as a dependency (turbo syntax, `"<package>#<task>"`):

```typescript
tasks: [{ name: "lint:code", turbo: { dependsOn: ["@theholocron/eslint-config#build"] } }];
```

### The repo that holds the reusables

The reusable workflows and composite actions that every repo's callers use are written in one repo, in its `ci/` folder (the private `@theholocron/ci` package). A repo with that package is the **home repo**: the `workflows` step does two things differently there.

- **Its callers call the reusable in the same checkout.** They are named `ci.<name>.yml` (so they do not clash with the reusable of the same name) and say `uses: ./.github/workflows/<flat name>.yml` (`test-unit.yml`, `lint-code.yml`), so a pull request that edits a reusable runs the edit. A caller's workflow `name:`, job and file are the task id (`ci.test-unit.yml` holds `name: test:unit` and the job `test-unit`), so its checks are named `test:unit / Conclusion`; the `ci` aggregate waits for them by the id before the slash. Any other repo keeps the names its callers had (`verification.unitTests.yml`, `name: Verification`) while they call the frozen reusables in `theholocron/.github`, because its ruleset lists those checks.
- **It writes the reusables themselves** into its `.github/workflows`, under flat file names, from `ci/workflows/<suite>/<leaf>.yml` (or `ci/workflows/<id>.yml` for a leaf in no suite): `ci/workflows/test/unit.yml` is `test-unit.yml`. The folder is the leaf's suite, so a file in the wrong folder fails a test. Only the ones that run when another workflow calls them: a reusable that is also started by an event or by hand (`tag`, `sync-dispatch`, `check-dispatched`) runs where it lives, so it is not copied.

Composite actions are not copied: a reusable called from another repository cannot see this checkout, so they stay on their full reference. Until the `ci-v1` tag exists that is the org's `.github` repository, and the home repo's own CI picks up a change to an action only after the actions are published there.

Every other repo keeps plain file names and calls the reusables by reference. `holocron probe generated check` covers the reusables like any other generated file.

## Options

| Option              | Description                           |
| ------------------- | ------------------------------------- |
| `[steps..]`         | Subset of steps to run (default: all) |
| `--repo owner/name` | Override repo coordinate              |
| `--dry-run`         | Print changes without writing         |

## Examples

```bash
# Sync everything
holocron repo sync

# Only sync labels and topics to GitHub
holocron repo sync labels topics

# Update local package.json fields without touching GitHub
holocron repo sync description homepage keywords scripts

# Dry-run all
holocron repo sync --dry-run
```
