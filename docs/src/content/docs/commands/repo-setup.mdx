---
title: "repo setup"
description: Apply all infra setup actions across every configured capability.
---

```bash
holocron repo setup [--repo owner/name] [--hooks | --no-hooks] [--dry-run]
```

`setup` is the primary provisioning command. It applies a deterministic set of infrastructure actions for every configured capability. Each step is wrapped in a try/catch — failures are reported but don't abort subsequent steps. A summary at the end shows counts for ok, fail, and skip.

## What setup does

### Always (no capability required)

| Action                       | Output                                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| Write `.editorconfig`        | Canonical editor settings (tab indent, LF line endings, etc.)                                         |
| Write `.alexrc.json`         | Shared inclusive-language allow-list                                                                  |
| Write `commitlint.config.ts` | CommitLint config extending `@theholocron/commitlint-config`                                          |
| Write `.husky/pre-push`      | When hooks are enabled — runs `holocron run ci` before every push (see below)                         |
| Update `codecov.yml`         | Syncs `individual_components` to match the workspace packages                                     |
| Write `turbo.json`           | Generated from the fan-out-eligible tasks in `tasks[]` — skipped when none are eligible               |
| Install CI workflows         | Writes `.github/workflows/<name>.yml` for each entry in `workflows[]`                                 |
| Install agent skills         | Downloads and installs each skill from `skills[]` into `.agents/skills/` with agent-specific symlinks |

### `source` capability (GitHub plugin)

| Action                                 | Notes                                                                   |
| -------------------------------------- | ----------------------------------------------------------------------- |
| Update repo settings                   | Squash-merge only, delete branch on merge, allow auto-merge             |
| Apply branch protection                | `balanced` = ruleset; `strict` = ruleset + required checks (see below)  |
| Enable vulnerability alerts            | Dependabot alerts                                                       |
| Enable automated security fixes        | Dependabot auto-PRs                                                     |
| Enable secret scanning                 | Secret scanning alerts                                                  |
| Enable private vulnerability reporting | Private advisories                                                      |
| Enable dependency graph                | Dependency graph + snapshot submission                                  |
| Enable CodeQL                          | Default setup with extended query suite                                 |
| Configure Dependabot                   | Writes `.github/dependabot.yml`                                         |
| Sync labels                            | Upserts canonical labels; removes stale ones                            |
| Sync properties                        | Sets org-level custom properties from `repo.properties`                 |
| Sync topics                            | Sets GitHub topics from `repo.topics`                                   |
| Sync variables                         | Creates and updates Actions variables from `repo.variables` (see below) |
| Sync teams                             | Grants team access from `repo.teams`                                    |
| Write `CODEOWNERS`                     | Generated for teams with write-or-higher permission                     |

**Required checks** (`protection: "strict"`) are derived from the task manifest —
`"DCO"` (hard-prepended), then every `{ required: true }` task's workflow check
context (`Lint / Conclusion`, `Test / Conclusion`, …) in CI order, then the
top-level `extraRequiredChecks`. No hand-maintained list.

**Pre-push hook.** When hooks are enabled — on by default for
`protection: "strict"`, gated by the `hooks` config field, overridable with
`--hooks` / `--no-hooks` — `setup` writes `.husky/pre-push` (runs `holocron run ci`)
and sets `package.json#scripts.prepare` to `husky` (unless `syncScripts: false`).
Run `pnpm install` once to activate it; bypass one push with `git push --no-verify`.

### `vault` capability

| Action              | Notes                                                                  |
| ------------------- | ---------------------------------------------------------------------- |
| `ensureProject`     | Creates the project container in the vault if absent                   |
| `ensureEnvironment` | Creates standard environments (`dev`, `stg`, `prd`) inside the project |

### `tooling` capability (Postman, etc.)

| Action   | Notes                                              |
| -------- | -------------------------------------------------- |
| `sync()` | Pulls the tool's authoritative state from the repo |

### `auth` capability (Clerk, etc.)

| Action             | Notes                                          |
| ------------------ | ---------------------------------------------- |
| `ensureWebhookApp` | Idempotent provisioning of the webhook backend |

## Options

| Option                   | Description                                                            |
| ------------------------ | ---------------------------------------------------------------------- |
| `--repo owner/name`      | Override the repo coordinate                                           |
| `--hooks` / `--no-hooks` | Force git-hook installation on or off (default: on for strict repos)   |
| `--dry-run`              | Print "would" lines for all mutating steps; read-only probes still run |

## Example

```bash
# Full setup
holocron repo setup

# Dry-run — see every action without executing
holocron repo setup --dry-run

# Target a specific repo
holocron repo setup --repo my-org/my-project
```

## Notes

- Workflow files written by `setup` are **generated artifacts** — overwritten on each run. Do not edit them manually; edit the workflow templates in `theholocron/holocron` and run `holocron sync github` instead.
- Skills are gitignored and re-installed on each `setup` run. Running `setup` on a fresh clone restores them.
- `setup` is idempotent — running it again on the same repo produces the same result and does not create duplicate labels, environments, or teams.

## Actions variables

Workflows read `vars.NAME`, and a missing one fails quietly, so declare them where the rest of the repository's settings live:

```ts
repo: {
  variables: {
    // This repository's variables.
    repo: { DEPLOY_REGION: "eu-west-1" },
    // The organization's. A string is visible to every repository.
    org: {
      TURBO_TEAM: "iamnewton",
      INTERNAL_ONLY: { value: "x", visibility: "private" },
    },
    // Delete variables that exist but are not declared above. Off unless you say so.
    prune: false,
  },
},
```

`holocron repo setup` creates what is missing, updates what differs and leaves what matches, then prints a summary such as `1 created, 1 updated, 5 unchanged, 2 not declared, left alone: LEGACY_FLAG, OLD_ONE`. Variables it does not declare are only listed, never deleted, unless `prune` is on. With `--dry-run` it still reads what exists and prints the plan, such as `would create 1, would update 1, 5 unchanged`, and changes nothing.

Values are stored in plain text and shown in the UI. Never declare a secret here; use the `secrets` capability for those. Names follow GitHub's rules: letters, digits and underscores, not starting with a digit or `GITHUB_`.

Declare organization variables in one repository only (the one that owns the organization's configuration), or two repositories will keep overwriting each other. `visibility: "selected"` (a hand-picked list of repositories) is not managed: use `all` or `private`. An existing variable limited to selected repositories is never deleted, even with `prune`; it is listed as not managed. Names are compared without regard to case, as GitHub does, and a scope declared empty (`repo: {}`) with `prune` deletes everything in it.

Tokens: repository variables use `HOLOCRON_ADMIN_TOKEN` (**Variables: read/write**), organization variables use `HOLOCRON_ORG_TOKEN` (organization **Variables: read/write**). See the [Token Reference](/holocron/tokens/).
