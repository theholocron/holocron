---
title: "doctor credentials"
description: Check that the credentials environment exists and holds the tokens the configured plugins take. Read-only, and it never reads a value.
---

```bash
holocron doctor credentials
```

Asks each `credentials` provider (a 1Password Environment) whether the environment `credentials.environment` names exists and which variables it holds, and compares them with the tokens the configured plugins take. It prints one row per provider, changes nothing and exits non-zero while the environment is missing or lacks an expected variable.

It never reads a value. The providers are loaded without being asked for their variables, so nothing is put in the process, and each one lists names only (for 1Password, `op environment secret list` without `--reveal`, where `op` prints a placeholder for every value and the check does not look at it).

```text
  ✗ credentials: 1password  "Holocron" has 2 variable(s): 1 problem(s)
      - missing variable HOLOCRON_CLOUDFLARE_TOKEN

0 ok, 1 fail, 0 skipped
```

## What must be there

Every `envName` in the `tokens` export of a configured plugin: the same list [`doctor tokens`](/holocron/commands/doctor-tokens/) walks (GitHub's nine, Discord's three, Sentry's two, ...). A variable the environment holds beyond those is never a problem. A plugin that cannot be loaded lists none here, and `doctor tokens` reports it.

The row says which spelling of the name matched. 1Password finds an Environment by its exact name and cannot list them, so the provider tries the name as written, then lowercase, Title case and UPPERCASE; when the one that matched is not the one the config writes, the row says so, and you can change the config to match.

## Skips

- **No `credentials` provider, or no `credentials.environment`**: a skip with the reason.
- **A provider that cannot list names without values**: a skip. The provider leaves the optional `inspect` method out.
- A provider that fails to load, or cannot find the environment (the row lists the spellings it tried), fails the row with its message.

## Authentication

None of its own. `op` signs in through the desktop app and Touch ID, or `OP_SERVICE_ACCOUNT_TOKEN` in CI. See [Tokens](/holocron/tokens/#credentials-providers).
