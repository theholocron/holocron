---
title: "doctor credentials"
description: Check that the credentials environment exists and holds the tokens the configured plugins take. Read-only, and it never reads a value.
---

```bash
holocron doctor credentials
```

Asks each `credentials` provider (a 1Password Environment) whether the environment `credentials.environment` names exists and which variables it holds, and compares them with the tokens the configured plugins take. It prints one row per variable, for each provider, changes nothing and exits non-zero while the environment is missing or lacks an expected variable.

It never reads a value. The providers are loaded without being asked for their variables, so nothing is put in the process, and each one lists names only (for 1Password, `op environment secret list` without `--reveal`, where `op` prints a placeholder for every value and the check does not look at it).

```text
  ✓ 1password: HOLOCRON_ADMIN_TOKEN        present in "Holocron"
  ✓ 1password: HOLOCRON_ORG_TOKEN          present in "Holocron"
  ✗ 1password: HOLOCRON_CLOUDFLARE_TOKEN   missing from "Holocron"
  · 1password: HOLOCRON_DISCORD_WEBHOOK    optional, not set in "Holocron"

2 ok, 1 fail, 1 skipped
```

## What must be there

Every `envName` in the `tokens` export of a configured plugin: the same list [`doctor tokens`](/holocron/commands/doctor-tokens/) walks (GitHub's nine, Discord's three, Sentry's two, ...). Each gets a row, named for the provider and the variable, in plain code-unit order so the output is the same on every machine, and the closing line counts variables, not providers.

| Row  | When                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| ok   | The environment holds the variable (an optional one that is set is just ok)   |
| fail | The environment lacks a variable a plugin needs: `missing from "Holocron"`    |
| skip | The environment lacks an optional variable: `optional, not set in "Holocron"` |

A token a plugin only falls back to is marked optional and is never a failure: the Discord plugin's webhook (`HOLOCRON_DISCORD_WEBHOOK`) is read only when a post names no channel, alias or default channel, so an environment without it passes. A name that any plugin lists as needed is expected. A variable the environment holds beyond those gets no row and is never a problem. A plugin that cannot be loaded lists none here, and `doctor tokens` reports it.

Every row says which spelling of the environment's name matched. 1Password finds an Environment by its exact name and cannot list them, so the provider tries the name as written, then lowercase, Title case and UPPERCASE; when the one that matched is not the one the config writes, the row says so (`present in "Holocron" (the config writes "holocron")`), and you can change the config to match.

## Skips

- **No `credentials` provider, or no `credentials.environment`**: a skip with the reason.
- **A provider that cannot list names without values**: one skipped row for the provider. It leaves the optional `inspect` method out.
- **No configured plugin lists a token**: one skipped row for the provider, since there is nothing to compare.
- A provider that fails to load, or cannot find the environment (the row lists the spellings it tried), fails one row for the provider with its message.

## Authentication

None of its own. `op` signs in through the desktop app and Touch ID, or `OP_SERVICE_ACCOUNT_TOKEN` in CI. See [Tokens](/holocron/tokens/#credentials-providers).
