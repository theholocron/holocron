---
title: "move issues"
description: Move the open items of one project board to another, with their status and priority. Closed items stay behind.
---

```bash
holocron move issues v4 v5            # asks first
holocron move issues v4 v5 --yes      # no question
holocron move issues v4 v5 --dry-run  # print what would happen, change nothing
holocron move issues v4 v5 --template sprint
```

Boards are named, not numbered: `<from>` may be closed already (a retired board), `<to>` must be open. Every open issue or pull request moves with its status and priority. A closed or merged one stays behind, and the provider sets it to a done status on the old board when it shows another. An item already on the target keeps its target values. This is the clean-up done by hand when one board replaces another.

```text
  ✓ move issues  "v4" to "v5"
      moved: 2 (#1, #2)
      kept (already on the target): 1 (#3)
      left (closed, stay on the old board): 1 (#4)
```

## It writes, so it asks

Without `--yes` it asks `Move the open items of "v4" to "v5"?` and moves nothing on a no. Without a terminal and without `--yes` it refuses instead of waiting for an answer.

`--dry-run` calls the provider's `items()` on both boards and prints what would move, be kept and be left, with `would` in front; it never calls `move` and never asks. A provider that cannot list items skips the preview.

## Which template

The template reads the boards' statuses (their categories say which one is "done"). It is `--template`, else the template the target board is declared with in `providers.projects.boards`, else the old board's, else `roadmap`.

## Skips

A provider without the optional `move` is skipped with a message naming it, and the exit code is 0. A missing board, an unknown template or a provider error fails with its reason.
