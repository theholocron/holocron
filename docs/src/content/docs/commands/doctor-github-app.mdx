---
title: "doctor github-app"
description: Compare each registered GitHub App's events, permissions and installations with its manifest file. Read-only.
---

```bash
holocron doctor github-app
```

GitHub has no API that changes an existing App's permissions or event subscriptions, so each instance (production `Sentinel`, `Sentinel - dev`) is changed by hand in its settings page, and a missed one fails quietly. This check compares the App manifest (`default_permissions`, `default_events`) with what each instance has now. It changes nothing and exits non-zero while any row fails.

## Declaring the instances

```ts
githubApps: [
	{ name: "Sentinel", manifest: "apps/sentinel/github-app.manifest.json", environment: "Sentinel" },
	{ name: "Sentinel - dev", manifest: "apps/sentinel/github-app.manifest.json", environment: "Sentinel - dev" },
],
```

`manifest` is a file in the directory. `environment` is the 1Password Environment (read through the `vault` provider, in memory, never printed or written) that holds `GITHUB_APP_ID` and `GITHUB_APP_PRIVATE_KEY`.

## The rows

For each instance the check signs the App's own JWT and calls `GET /app` and `GET /app/installations`.

| Row             | Passes when                                                                                                                                                                                               |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `reachable`     | the credentials are read and GitHub accepts the JWT                                                                                                                                                       |
| `events`        | every manifest event is subscribed. Extra events are named in the row as `info`                                                                                                                           |
| `permissions`   | every manifest permission is granted at least at the manifest's level (`read < write < admin`). Extra permissions are `info`                                                                              |
| `installations` | no installation lags the App: each has accepted every permission and event the App asks for. A pending update (the App changed, the owner has not accepted) fails, naming the installation's page to open |

A failing `events` or `permissions` row ends with the exact page: `https://github.com/organizations/<org>/settings/apps/<slug>/permissions` for an organization-owned App, `https://github.com/settings/apps/<slug>/permissions` for a user-owned one (events are on the same page, under "Subscribe to events").

## Skips

An instance whose credentials cannot be read (no `vault` provider, the environment missing or not signed in, no `GITHUB_APP_ID` or key in it) is a skip with the reason, not a failure. A manifest that does not read, or a JWT GitHub rejects, fails.
