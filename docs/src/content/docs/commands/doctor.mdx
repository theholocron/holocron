---
title: "doctor"
description: Load every configured capability and run a smoke check against each provider.
---

```bash
holocron doctor [--repo owner/name] [--dry-run]
```

`doctor` loads the config, instantiates every capability, and runs a lightweight probe against each provider. Use it to confirm authentication and connectivity before running `setup` or after rotating a token.

## What each capability checks

| Capability | Smoke check                                                                |
| ---------- | -------------------------------------------------------------------------- |
| `source`   | `whoami()` — verifies the token and returns the authenticated login        |
| `issues`   | `doctor()` — validates lifecycle slot mapping and lists available statuses |
| `secrets`  | `listSecrets({ kind: 'repo' })` — lists secret names at repo scope         |
| `ci`       | `listRuns({ limit: 1 })` — fetches the most recent CI run                  |
| `vault`    | `list()` — lists available secret keys                                     |
| `auth`     | `whoami()` — verifies the auth provider key                                |
| Others     | "loaded" — confirms the plugin loads without error                         |

## Output

```
Holocron doctor — my-project
  config: /path/to/holocron.config.ts

  source    github    ✓  authenticated as cnewton
  ci        github    ✓  1 run found
  secrets   github    ✓  3 secrets
  issues    github    ✓  authenticated as cnewton / Repo: my-org/my-project
  vault     doppler   ✓  12 secrets

Summary: 5 ok, 0 fail, 0 skip
```

Exit code is 1 if any capability reports `fail`.

## Options

| Option              | Description                                                     |
| ------------------- | --------------------------------------------------------------- |
| `--all`             | Run every deep check and print one row each (see below)         |
| `--repo owner/name` | Override the repo coordinate (defaults to config or git remote) |
| `--dry-run`         | No-op for doctor — read-only checks still run                   |

## Going deeper

`holocron doctor` only asks whether each provider can be reached. To compare what a provider is _declared_ to have with what it actually has, run the capability's own check: [`holocron doctor notifications`](/holocron/commands/doctor-notifications/) checks the notification server layout step by step, [`holocron doctor variable-owners`](/holocron/commands/doctor-variable-owners/) flags a variable name that lives in more than one place (1Password Environments and GitHub Actions), [`holocron doctor shared-values`](/holocron/commands/doctor-shared-values/) finds secrets that hold the same value in two layers (`local`, `dev`, `ci`, `prod`), [`holocron doctor monitoring`](/holocron/commands/doctor-monitoring/) checks that the monitoring checks the provider declares exist in its account, and [`holocron doctor repo`](/holocron/commands/doctor-repo/) checks the repository settings `setup` writes (description, topics, labels, teams, branch protection, security), [`holocron doctor secrets`](/holocron/commands/doctor-secrets/) checks that the secrets the config relies on exist, [`holocron doctor project`](/holocron/commands/doctor-project/) compares each declared project board with its template, [`holocron doctor secrets`](/holocron/commands/doctor-credentials/) checks that the credentials environment exists and holds the tokens the plugins take, [`holocron doctor secrets`](/holocron/commands/doctor-secrets/) checks that the tokens the plugins take are set and still accepted, [`holocron doctor dns`](/holocron/commands/doctor-dns/) checks the DNS records setup writes, [`holocron doctor ci`](/holocron/commands/doctor-ci/) checks the repository against the flat task vocabulary (deprecated aliases, caller names, the `ci` aggregate), [`holocron doctor github-app`](/holocron/commands/doctor-github-app/) compares each registered GitHub App's events, permissions and installations with its manifest, [`holocron doctor logs`](/holocron/commands/doctor-logs/) checks that the Axiom datasets the setup ships logs to exist and the token reaches them, and [`holocron doctor environments`](/holocron/commands/doctor-environments/) checks that the deployment environments exist.

## Running every deep check

```bash
holocron doctor --all
```

Runs every deep check in turn and prints one row for each, then the closing count of checks. It is the one command for a scheduled run, or for a person after a large change. It also runs from the interactive menu as `doctor › doctor (everything)`.

```text
  ✓ notifications  8 ok
  ✗ variables      1 failed
      - run `holocron doctor secrets` for the steps

1 ok, 1 fail, 0 skipped
```

- **One row per check, not per step.** A failing row names the command that shows its steps.
- **A check that cannot run is a skip.** No provider, no token, or nothing declared to compare shows as a skip with the reason (for example `no source provider to read them with`), and does not fail the run.
- **Any other error fails that check only.** The checks after it still run.
- **It exits 1 when any check did not pass**, and 0 otherwise.
- **It changes nothing.** `doctor notifications` on its own leaves one labelled test post in the layout's test channel; inside `--all` it runs as `--built-only`, which posts nothing. Run `holocron doctor notifications` for the delivery check.
- **It is the deep checks, not the smoke check too.** Plain `holocron doctor` is the smoke check and stays a separate command.
