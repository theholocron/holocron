---
title: "doctor secrets"
description: Check that the secrets the config relies on exist. Read-only, names only.
---

```bash
holocron doctor secrets
```

Compares the secret names the config says must exist with the names the `secrets` provider holds, and prints one row for each scope that has something expected: the repository, the organization and each environment. It changes nothing, shows no value (GitHub never returns one), and exits non-zero while any row fails.

A workflow that reads a secret which does not exist fails quietly, and a secret is easy to forget when a repo is set up by hand. This is the check that says which are missing. To see everything that does exist, use [`secrets list`](/holocron/commands/secrets-list/).

```text
  ✓ repository secrets exist    2 of 2 exist
  ✗ organization secrets exist  2 problem(s)
      - missing secret HOLOCRON_NOTIFY_WEBHOOK_SYNC
      - missing secret NPM_TOKEN

1 ok, 1 fail, 0 skipped
```

## What must exist

Nothing is expected beyond these, and a secret that exists but is not expected is never a problem, since many legitimate ones are not listed anywhere.

| Scope        | Expected                                                                                                                                                                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repository   | `repo.secrets.repo`, and the Chromatic token of each project of a `verification.visualRegression` task: `CHROMATIC_PROJECT_TOKEN` for `tokenName: "default"` (or none), otherwise `CHROMATIC_PROJECT_TOKEN_<TOKENNAME>`                                                      |
| Organization | `repo.secrets.org`, and the secrets the notification layout fills: each channel's webhook secret (`webhook.secret`, else `HOLOCRON_NOTIFY_WEBHOOK_<CHANNEL>`) and each role's `secret`. The organization is `--org`, `HOLOCRON_ORG`, the config's `org`, or the repo's owner |
| Environment  | `repo.secrets.environments.<name>`                                                                                                                                                                                                                                           |

Declare the rest in `holocron.config.ts`. Names only, never values; `secrets set` and `secrets sync` write them.

```ts
repo: {
  secrets: {
    repo: ["TURBO_TOKEN", "VERCEL_TOKEN"],
    org: ["NPM_TOKEN"],
    environments: { production: ["DATABASE_URL"] },
  },
},
```

Names are compared without regard to case, as GitHub does. Fragments from presets add up: each list is a union.

## Skips

A row is a **skip**, not a failure, when it cannot be read: no `secrets` provider is configured or it failed to load, or the provider has no token for that scope. When nothing is expected anywhere, the one row says `none declared`.

A row **fails** when a secret is missing, when there is an organization secret to look for but no organization to look under, and when the provider reports an error for that scope (for example an environment that does not exist).

## Authentication

Reads use the same tokens as [`secrets list`](/holocron/commands/secrets-list/): `github.secrets` for the organization scope, `github.admin` for the repository and environments.

`doctor notifications` keeps its own step for the layout's secrets, so a problem there shows in both.
