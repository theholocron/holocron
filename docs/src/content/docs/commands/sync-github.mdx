---
title: "sync github"
description: Sync workflow templates and composite actions to theholocron/.github via the GitHub API.
---

```bash
holocron sync github [--repo owner/repo] [--branch <branch>] [--pr] [--message <msg>] [--output-dir <path>] [--dry-run]
```

Generates the files `theholocron/.github` still serves (starter workflows and the workflows that run there) from the source-of-truth templates and pushes them to `theholocron/.github` (or any target repo). This is an internal CI command — the `sync-workflow-templates` workflow in holocron itself runs it automatically on push to `main`.

## Options

| Option         | Default                                 | Description                                                                           |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------- |
| `--repo`       | `theholocron/.github`                   | Target `owner/repo` to push generated files to                                        |
| `--branch`     | _(default branch)_                      | Push to this branch instead of the default branch                                     |
| `--pr`         | `false`                                 | Open a PR after pushing to `--branch` (no-op without `--branch`)                      |
| `--message`    | `chore: sync from theholocron/holocron` | Commit message                                                                        |
| `--output-dir` | —                                       | Write generated files to a local directory instead of pushing (useful for validation) |
| `--dry-run`    | `false`                                 | Print what would be pushed without calling the GitHub API                             |

## Examples

```bash
# Push to theholocron/.github default branch
holocron sync github

# Push to a PR branch (useful for protected repos)
holocron sync github --branch chore/sync --pr

# Write locally for inspection
holocron sync github --output-dir /tmp/sync-preview

# Dry-run
holocron sync github --dry-run
```

## Moving off `theholocron/.github`

The reusable workflows and composite actions are written in [`ci/`](/holocron/commands/repo-sync/#the-repo-that-hosts-the-reusables) in holocron and run from there. `theholocron/.github` keeps what GitHub reads only from the org's `.github` repository: the community-health files, the profile and the starter workflows.

What happens to the copies that `.github` already holds:

- **They are frozen.** `sync github` no longer pushes the 30 moved reusable workflows or the 7 composite actions. A repo that still calls `theholocron/.github/.github/workflows/<name>.yml@main` keeps working, with the version of the workflow it had when the copy was frozen. Nothing new reaches it.
- **Each carries a notice.** The first `sync github` after the move adds a `# DEPRECATED — frozen copy.` block below the file's header (what replaces it, when it goes, the tracking issue) and leaves the file alone after that. A file that says so is the way to tell a repo is still on the old path; so is `holocron probe ci refs`, which counts the references.
- **They go when nothing refers to them.** `holocron probe ci refs` over the org reports zero, and the copies are deleted.
- **Not frozen:** the workflows that run where they live (`tag`, `sync-dispatch`, `platform.dispatchedCheck`), the starter workflows and their metadata, and the nine hand-written workflows (`audit`, `deploy`, `lint`, `release`, `security`, `sync`, `test`, `typecheck`, `wiki`), which the templates still call and which are not generated by this command.

Why frozen copies and not a forwarding workflow in their place: a reusable workflow that calls another adds a level to the name of every check it posts (`Test / Conclusion` becomes `Test / <forwarding job> / Conclusion`), and a required check is matched by that name. Every repo still on the forwarding file would stop posting the checks its ruleset requires. Moving a repo is a one-line change of the `uses:` reference, so it keeps the same names.

To move a repo, change `theholocron/.github/.github/workflows/<name>.yml@main` to `theholocron/holocron/.github/workflows/<name>.yml@ci-v1`.

## Authentication

Uses `HOLOCRON_SYNC_TOKEN` / `github.sync` keyring entry. Required scopes: `contents: read/write`, `pull_requests: read/write`, `workflows: read/write`.

When `--output-dir` is set, no GitHub API calls are made and no token is required.

## Notes

- No super-linter — each `sourceQuality.*`/`security.*`/`platform.commitStandards` reusable workflow runs its own tool(s) directly, the same command `holocron run <task>` resolves locally.
- If the target repo has branch protection on its default branch, use `--branch` + `--pr` to create a pull request that can be reviewed before merging. **`--pr` is a no-op without `--branch`** — passing `--pr` alone pushes straight to the default branch.
- A closed-but-existing branch blocks future PR creation. If you close a sync PR without merging, delete the branch as well: `gh pr close <n> --delete-branch`.
