title: "doctor ci"
description: Check a repository against the flat task vocabulary - aliases, caller names, the ci aggregate and where the callers point. Read-only.
---

```bash
holocron doctor ci [--shadow [--limit <n>]]
```

Answers one question for the repository you are in: has it moved to the flat task vocabulary (spec `ci-flat-task-vocabulary`)? It reads `holocron.config.ts` and `.github/workflows`, needs no provider or token, changes nothing, and exits non-zero while any row fails. Run it before and after repointing a repository's callers.

```text
  ✓ tasks use flat ids                       26 of 26 use flat ids
  ✓ callers are named for their task id      29 of 29 named for their id
  ✓ ci aggregate lists the configured tasks  15 of 15 ids match
  ✓ callers point at one home                this repo's own reusables (flat names)

4 ok, 0 fail, 0 skipped
```

## The rows

| Row         | Passes when                                                                                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| `tasks`     | no `tasks:` entry in the config is a deprecated alias (`delivery.build`, `validate`, `stale`, ...). A failing line names the flat id or ids that replace it                                            | {/* holocron-allow-old-name */} |
| `callers`   | each generated caller's file, workflow `name:` and job `name:` equal its task id. A file still named for an old task (`ci.verification.unitTests.yml`) is reported with the flat name that replaces it |
| `aggregate` | the `expected` list in the `ci` aggregate caller (`ci.ci.yml`) is the list the configured tasks derive: no id missing, none stale                                                                      |
| `home`      | every caller calls reusables from one home: `theholocron/.github` (frozen copies, legacy names), holocron at `ci-v1` (flat names) or the repo's own reusables (the repo that contains them)            |

A job name may carry a suffix after the id (`release ${{ matrix.group }}`). Only generated callers are read (the `AUTO-GENERATED` header and a job that calls a reusable workflow); hand-written workflows and the reusables themselves are left alone.

## Comparing Sentinel's shadow (`--shadow`)

While Sentinel's `ci` aggregate runs in shadow (spec `process-sentinel-posts-ci`, SPEC-0099), `--shadow` adds a `shadow` row that answers whether the two checks say the same thing. It reads, through the `source` provider (so it needs a token; the other rows need none), the newest `--limit` open and merged pull requests (default 40) and, for each head commit, the newest `ci / Required checks` run (the Actions poller) and the newest `ci / Required checks (sentinel)` run.

- A pull request is **decided** when both posted and neither is still running. One the shadow never posted on, and one still running, are left out: neither says the two disagree.
- **Any decided pull request where they differ fails the row**, and each is named with what each side said.
- With none decided the row is a skip. Below 20 consecutive agreeing pull requests it is a skip too (the shadow is still being watched); at 20 it passes. That is the spec's exit criterion for the dev instance (10 for the production shadow, by hand).

The spec also asks that the agreeing set include a re-run of one leaf, a cancelled first batch (#2171), a `codecov/*` status that arrives late, a skipped leaf and a missing id. The row cannot tell which pull requests those were; a person reads that off the pull requests it lists.

## Skips

`callers`, `aggregate` and `home` are skips, not failures, when there is nothing to look at: no generated caller, or no `ci` aggregate caller (only the repository that contains the reusables writes one today). The `tasks` row always runs.

While `CI_HOME.ref` is `main`, `holocron sync` still writes the legacy caller names in a repository that does not host the reusables, so such a repository fails `callers` until its callers are repointed at `ci-v1`. The `home` row says which side it is on.
