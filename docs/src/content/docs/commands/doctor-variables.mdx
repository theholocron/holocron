---
title: "doctor variables"
description: Check the Actions variables declared in repo.variables against the ones the provider holds. Read-only.
---

```bash
holocron doctor variables
```

Compares the Actions variables `repo.variables` declares in `holocron.config.ts` with what the `source` provider holds, and prints one row for the repository's variables and one for the organization's, each only when the config declares that scope. It changes nothing, and it exits non-zero while any row fails.

It is the check for [`repo setup`](/holocron/commands/repo-setup/), which writes the variables. A workflow that reads a variable which is missing or wrong fails quietly, so run it after `repo setup` and whenever a workflow warns that a `vars.*` value is unset.

```text
  ✓ repository variables match    2 of 2 match
  ✗ organization variables match  2 problem(s)
      - organization variable CLOUDFLARE_ACCOUNT_ID: declared "abc123" (all), found "abc123" (private)
      - missing organization variable TURBO_TEAM

1 ok, 1 fail, 0 skipped
```

## What counts as a problem

| Finding                                                 | A problem when                                                                                          |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A declared variable is missing                          | always                                                                                                  |
| A declared variable has another value                   | always                                                                                                  |
| An organization variable has another visibility         | the declaration states one, or it is a bare string (which means `all`)                                  |
| A variable exists but is not declared                   | only with `repo.variables.prune: true`. Without it `repo setup` leaves it alone, so the doctor does too |
| An undeclared variable limited to selected repositories | never: this CLI does not manage those                                                                   |

Names are compared without regard to case, as GitHub does. Values are plain text, so they appear in the problem lines.

## Skips

A row is a **skip**, not a failure, when it cannot be read:

- no `source` provider is configured or it failed to load,
- the provider cannot list variables, or
- the organization row needs the org token (`HOLOCRON_ORG_TOKEN`, or `holocron auth set github.org`) and there is none.

When nothing is declared at all, the one row says `none declared`.

## Authentication

Repository variables use the same token `repo setup` uses (`github.admin`, with variables read access). Organization variables use the org token (`github.org`) with the organization's variables read permission.
