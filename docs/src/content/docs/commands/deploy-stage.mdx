---
title: "deploy stage"
description: Assemble the payload that `deploy --files` uploads for a Vercel Function package.
---

```bash
holocron deploy stage [--package-dir <dir>] [--out <dir>]
```

Writes `.vercel-deploy/` for a package that ships as a Vercel Function (Sentinel), so `holocron deploy --files .vercel-deploy` uploads exactly that and nothing else:

- `api/webhook.mjs`, `vercel.json` and `dist/index.mjs` copied from the package (run its `build` first),
- a trimmed `package.json` with the name, version, `type`, `engines` and `dependencies` only, each dependency pinned to the version installed in `node_modules` (Vercel's `npm install` cannot read `workspace:` or `catalog:` specifiers).

An `@theholocron/*` dependency installed at an `alpha` prerelease is pinned to the version npm's `alpha` tag points at instead. A workspace package's `package.json` is not updated when it is released (the plugins sit at `5.0.0-alpha.132` on disk and are far past that on npm, and each peers on exactly one CLI version), so the installed version would stage a stale plugin beside a newer CLI. Each change is printed. The lookup is `npm view <name>@alpha`: a package without an `alpha` tag keeps its installed version, and the command fails, writing nothing, when npm cannot be reached.

A release publishes its packages one after another, so a stage that starts during one can read some tags before it and some after. When a pinned release peers on an exact version of another staged package that differs from the one staged, the command says so, waits and looks the tags up again (after 15, 30, 60 and 60 seconds). If they still disagree it fails, writing nothing, and names each package and the versions that differ, because Vercel's install would reject that tree. Run the deploy again once the release has finished.

`engines.node` is rewritten to the `<major>.x` form Vercel accepts (`>=22` becomes `22.x`).

It refuses, before writing anything, when `dist/index.mjs` imports a package that is not in the package's `dependencies`: Vercel would not install it and the function would crash on import.

## Options

| Option          | Default                    | Description                |
| --------------- | -------------------------- | -------------------------- |
| `--package-dir` | the current directory      | The package to stage       |
| `--out`         | `<package>/.vercel-deploy` | Where to write the payload |

## Examples

```bash
# What Sentinel's deploy script runs
pnpm run build && holocron deploy stage && holocron deploy --files .vercel-deploy --project-id sentinel
```
