# Note 3 — `@theholocron/components-doc`

**Repo:** `theholocron/docs` monorepo, `packages/components-doc/`
**Depends on:** Note 1 (`registry-doc` published). Can be developed in parallel
with Note 1 once types are stable.

---

## Problem

Docs pages across `clients` and `holocron` are structurally identical — same
heading order, same install block, same table layout. Design changes (new badge,
different heading, sandbox embed) require editing 30+ pages by hand. Some get
missed.

The unique content per page is small:

- Usage / code examples
- Config options (plugins only)
- Auth steps (plugins only — partially templatable)

Everything else is derivable from `registry-doc` data.

---

## Components

All are Astro components, exported from a single subpath:

```ts
import { PackageHeader, Installation, PluginHeader, CapabilitiesTable, PackageGrid } from "@theholocron/components-doc";
```

---

### `<PackageHeader>` — for client pages

```ts
interface PackageHeaderProps {
  entry: LinkEntry; // from getClients()[slug]
}
```

Renders:

- Package name as inline code
- One-line description
- npm badge → `entry.npmUrl`
- GitHub badge → `entry.githubUrl`
- Sandbox link (conditional on `entry.sandboxUrl`)

---

### `<PluginHeader>` — for plugin pages

```ts
interface PluginHeaderProps {
  entry: LinkEntry; // from getPlugins()[slug]
  capability: string; // "observability"
}
```

Same as `<PackageHeader>` but adds a capability label/badge.

---

### `<Installation>`

```ts
interface InstallationProps {
  package: string; // "@theholocron/github-client"
  dev?: boolean; // default false; plugins use true
  global?: boolean; // default false; CLI tools use true
}
```

Renders a `## Install` heading + `pnpm add [-D|-g] {package}` code block.

---

### `<CapabilitiesTable>` — for plugin pages

```ts
interface CapabilitiesRow {
  capability: string; // "observability"
  token: string; // "HOLOCRON_SENTRY_TOKEN (sentry)"
}
interface CapabilitiesTableProps {
  rows: CapabilitiesRow[];
}
```

Renders a `## Capabilities` heading + standard two-column table. Replaces the
hand-maintained table currently in every plugin page.

---

### `<PackageGrid>` — for index / overview pages

```ts
interface PackageGridProps {
  packages: LinksRegistry; // full registry or subset
  type?: "clients" | "plugins"; // controls column labels; default "clients"
}
```

Renders a table: Package | Description | Docs | npm.
Used on `docs/index.mdx` of clients and the plugin overview page in holocron.
This is what makes `index.mdx` fully component-driven with no hardcoded content
(see Note 4).

## Full page examples

### Client page (`clients/docs/src/content/docs/github.mdx`)

```mdx
---
title: GitHub Client
description: TypeScript client for the GitHub REST API.
---

import { PackageHeader, Installation } from "@theholocron/components-doc";
import { getClients } from "@theholocron/registry-doc";
export const entry = getClients()["github-client"];

<PackageHeader entry={entry} />
<Installation package={entry.package} />

## Usage

\`\`\`ts
import { createGitHubClient } from "@theholocron/github-client";
const client = createGitHubClient({ token: process.env.GITHUB_TOKEN });
\`\`\`

{/* API reference is auto-generated by starlight-typedoc — link, don't reproduce */}
See [API Reference](/github/api) for all namespaces and methods.
```

### Plugin page (`holocron/docs/src/content/docs/plugins/sentry.mdx`)

```mdx
---
title: Sentry Plugin
description: Implements the observability capability against Sentry's management API.
---

import { PluginHeader, Installation, CapabilitiesTable } from "@theholocron/components-doc";
import { getClients, getPlugins } from "@theholocron/registry-doc";
export const plugin = getPlugins()["holocron-plugin-sentry"];
export const client = getClients()["sentry-client"];

<PluginHeader entry={plugin} capability="observability" />
<Installation package={plugin.package} dev />
<CapabilitiesTable rows={[{ capability: "observability", token: "HOLOCRON_SENTRY_TOKEN (sentry)" }]} />

This plugin uses [{client.package}]({client.docsUrl}) under the hood.

## Config

\`\`\`ts
providers: { observability: ["sentry", { org: "my-org" }] }
\`\`\`

...rest of page (auth steps, what the capability provides, example)...
```

## Package structure

```
packages/components-doc/
  src/
    PackageHeader.astro
    PluginHeader.astro
    Installation.astro
    CapabilitiesTable.astro
    PackageGrid.astro
    index.ts              ← re-exports all components
  src/__tests__/          ← snapshot or build tests
  tsconfig.json
  tsdown.config.ts        ← or astro build for component lib
  package.json
  README.md
```

**Note:** Astro component libraries require `@astrojs/check` for type-checking
and a different build setup than a standard tsdown package. Check current
`@theholocron/docs-theme` scaffold for the right build pattern — mirror it here.

---

## Sandbox embeds (deferred)

`PackageHeader` renders a sandbox link only when `entry.sandboxUrl` is set.
No inline `<iframe>` embed in this spec — sandbox platform choice (StackBlitz
WebContainers vs CodeSandbox) is a separate decision. Add `sandboxUrl` entries
to `registry-doc` as sandboxes become available.
